# GymOps

Система управления сетью фитнес-клубов: клиенты, абонементы, продажи, посещения,
расписание и отчётность.

Проект в разработке. Текущий релиз — v0.1: рабочее место администратора
ресепшена и сводка для владельца.

## Стек

Python 3.14 · Django 6.1 · PostgreSQL 17 · psycopg 3 · uv

Обоснование каждого выбора — в [ADR-0001](docs/decisions/0001-stack.md).

## Требования

- [uv](https://docs.astral.sh/uv/) — управление окружением и зависимостями.
  Версию Python устанавливать отдельно не нужно: uv поставит ту, что указана
  в `.python-version`
- [Docker](https://docs.docker.com/get-docker/) с плагином Compose — база
  данных поднимается только в контейнере, локально PostgreSQL ставить не нужно

## Запуск окружения

```bash
git clone https://github.com/decemlabs/GymOps.git
cd GymOps
uv sync
```

`uv sync` создаёт виртуальное окружение и ставит зависимости **строго тех
версий, что записаны в `uv.lock`** — одинаково на любой машине и в CI.

Проверка:

```bash
uv run python -c "import django; print(django.get_version())"
```

Ожидаемый вывод — `6.1`.

Команды в окружении запускаются через `uv run`, активировать его вручную не
требуется.

## База данных

PostgreSQL 17 работает в контейнере. Версия зафиксирована явно, не `latest`:
каталог данных несовместим между мажорными версиями, и молчаливое обновление
образа сломало бы уже существующую базу.

### Переменные окружения

Настройки подключения читаются из `.env` в корне проекта. Файл в репозиторий не
попадает — он в `.gitignore`. Шаблон со списком переменных лежит рядом:

```bash
cp .env.example .env
```

После копирования задать `POSTGRES_PASSWORD` — у него нет значения по
умолчанию, и без него контейнер не стартует.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `POSTGRES_DB` | `gymops` | Имя базы, которую создаёт контейнер при первом запуске |
| `POSTGRES_USER` | `postgres` | Владелец базы |
| `POSTGRES_PASSWORD` | — | Пароль. Обязателен: без него не стартует ни контейнер, ни Django |
| `POSTGRES_HOST` | `localhost` | Хост базы со стороны Django. В контейнере станет именем сервиса |
| `POSTGRES_PORT` | `5432` | Порт на хосте. Менять, если 5432 уже занят другим PostgreSQL |

### Запуск и остановка

```bash
docker compose up -d
```

```bash
docker compose down
```

`down` останавливает и удаляет контейнер, но **не трогает данные**: они лежат
в именованном томе `postgres_data` и переживают пересоздание контейнера.
Следующий `up` поднимет ту же базу с теми же таблицами.

### Проверка подключения

Проверять нужно **снаружи контейнера**. Внутри база доступна всегда, а вот
публикация порта на хост — ровно то, что способно не сработать незаметно, и
именно ею будет пользоваться Django.

Отдельный клиент для этого ставить не нужно: `psycopg` уже в зависимостях
проекта, и приложение пойдёт в базу через него же.

```bash
uv run python -c "import psycopg; print(psycopg.connect('postgresql://postgres:пароль@localhost:5432/gymops').execute('select version()').fetchone()[0])"
```

Подставить свой пароль из `.env` — и пользователя, если менял. Ожидаемый вывод
— строка, начинающаяся с `PostgreSQL 17.`

Если нужен интерактивный psql, он есть внутри контейнера:

```bash
docker compose exec db psql -U postgres -d gymops
```

Эта команда работает и тогда, когда порт наружу не проброшен, — как проверку
подключения засчитывать её нельзя.

### Полный сброс базы

Удаляет том вместе со всеми данными — операция необратима:

```bash
docker compose down -v
```

## Настройки Django

Настройки — пакет `src/config/settings/`, а не один файл:

| Модуль | Когда | Чем отличается |
|---|---|---|
| `base.py` | всегда, через импорт | общее для всех окружений |
| `local.py` | разработка, **по умолчанию** | `DEBUG = True`, ключ с dev-заглушкой |
| `production.py` | прод | `DEBUG = False`, HTTPS-заголовки, все секреты обязательны |
| `test.py` | тесты | быстрый хэшер паролей |

Файлы задают структуру и отличия окружений, значения приходят из переменных
окружения — [ADR-0005](docs/decisions/0005-project-structure.md).

Модуль выбирается переменной `DJANGO_SETTINGS_MODULE`. Точки входа
(`manage.py`, `wsgi.py`, `asgi.py`) подставляют `config.settings.local`, если
переменная не задана, — поэтому локально её задавать не нужно, а прод обязан
указать свою явно.

Настройки читают `.env` сами — через `django-environ`, экспортировать
переменные в оболочку не нужно:

```bash
uv run python manage.py check
```

Ожидаемый вывод — `System check identified no issues`.

Приоритет такой: то, что уже есть в окружении процесса, побеждает; `.env`
только заполняет недостающее. Поэтому локально работает файл, а в проде, где
никакого `.env` нет, значения приходят из окружения контейнера.

Если обязательная переменная не найдена нигде, запуск падает сразу:
`ImproperlyConfigured: Environment variable POSTGRES_PASSWORD is required`.
Это задумано — молчаливых умолчаний вместо недостающих секретов нет.

Ожидаемый вывод — `System check identified no issues`. Без переменных запуск
падает с `ImproperlyConfigured: Environment variable POSTGRES_PASSWORD is
required` — это задумано: настройки не подставляют молчаливых умолчаний вместо
недостающих секретов.
